# Demo, evidence, and honest evaluation

## Core demonstration

Open: "A study group can agree without understanding. RELAY gets the group together, lets
people think independently, helps them explain to each other, and checks a new application."

Show the actual Discord server. Four accounts join. Show one manual time proposal and its
versioned confirmations; say that .ics is available and Google OAuth is deferred.

Start the percentage-change fixture. Ask each real participant for an independent answer.
Do not force the participants to choose a wrong answer. For a rehearsed alternative, disclose
that the initial responses are synthetic. No staged result is a user-study finding.

Show the peer prompt, a voluntary explanation, and a fresh question. Let a judge choose an
answer or challenge the question. A challenge pauses scoring; a discarded question does not
produce a confident learning score. This is a stronger trust demonstration than a fake 100% badge.

Show the debrief with denominators and a delayed check that is PENDING. Do not fast-forward the
clock and call the result real retention. A simulated clock test is fine when clearly labeled.

Close: "Relay does not replace the group with a tutor. It helps the group teach one another,
and records what participants can apply independently afterward."

## Useful metrics

- Valid private attempts / invited participants (distinguish missing and skipped).
- Same-participant initial/fresh item outcomes, with item IDs and denominators.
- Delayed responses when actually due; nonresponses are missing data, not failures.
- Human-reviewed correctness and source relevance of hints.
- Premature answer leakage in discussion prompts.
- Stale proposal rejection, consent revocation, duplicate delivery behavior.
- Observed response latency and provider tokens/cost, not invented dashboard values.

## Do not claim

"Proves understanding", "raises grades", "100% private", "zero hallucinations", "best model",
"scientifically validated", or "all students mastered the concept". Immediate matched-question
performance is not causal learning evidence. Question difficulty and prior knowledge can differ.

## A stronger later evaluation

Compare peer-discussion and individual-review conditions with comparable question pairs,
randomized/counterbalanced assignment, the same time budget and tools, and an independently
scored delayed test. A four-person hackathon demonstration is not sufficient for a broad
causal claim. Let students opt out of publishing results and avoid live graded assessments.

## Human acceptance test list

- Everyone initially wrong; nobody is publicly shamed.
- Everyone initially right; still check a different application without declaring mastery.
- Correct choice with weak reasoning; do not label the student an expert.
- Confident wrong response; use a possible misconception prompt, not a diagnosis.
- Unsupported source or ambiguous wording; challenge, pause, and discard if needed.
- Model failure; clearly labeled reviewed fallback, core flow still works.
- Participant privately chooses SKIP; never counted as incorrect.
- A participant vanishes; do not fabricate their response. Current MVP needs their SKIP or a
  future explicit timeout/withdrawal feature; disclose this limitation.
- Calendar information missing; unknown is not free.
- All approvals received, then time changes; old buttons must fail.
- Consent revoked before delivery; job cancelled.
- Discord returns a rate limit or ambiguous timeout; use the documented handling.
